# 아키텍처와 설계 결정

## 구성

```
┌──────────────── UI 스레드 (React) ────────────────┐        ┌──────── Web Worker ────────┐
│ App ─ ControlPanel (설정 → postMessage)           │  msg   │ sim.worker.ts              │
│     ─ SimCanvas  (rAF 루프, client.latest 읽음)   │ ─────▶ │  고정 dt 루프 + 시간 예산   │
│     ─ StatsPanel (1 Hz, client.history 읽음)      │ ◀───── │  Simulation (순수 TS)       │
│     ─ HUD        (4 Hz 폴링)                      │ frame  │  스냅샷: Float32Array 전송  │
└───────────────────────────────────────────────────┘        └────────────────────────────┘
```

| 경로 | 역할 | DOM 의존 |
|---|---|---|
| `src/sim/` | 엔진: 타입, RNG, 유전체, 공간 격자, 충돌, 엔진, 프리셋 | 없음 (Node에서 테스트) |
| `src/worker/` | Worker 루프와 메시지 프로토콜 | Worker API |
| `src/client/` | Worker 핸들, 최신 프레임, 통계 이력 | Worker API |
| `src/render/` | Canvas 2D 렌더러, 카메라, 클릭 선택 | Canvas |
| `src/ui/` | React 컴포넌트, 차트 데이터 변환 | React |
| `scripts/` | 헤드리스 튜닝(`tune`), 반복 실험(`replicate`), 벤치마크(`bench`) | 없음 |

## 결정 기록

### D1. 엔진은 순수 TypeScript, DOM 없음
엔진은 Worker, Node 테스트, 헤드리스 스크립트에서 같은 코드로 돌아갑니다. 헤드리스 고속 실행(요구사항 10)이 이미 `scripts/replicate.ts`로 가능합니다.

### D2. Structure-of-Arrays + TypedArray
개체 필드마다 TypedArray 하나를 씁니다(`x: Float64Array`, `species: Uint8Array`, 유전체는 stride 5인 `Float64Array`). 객체를 할당하지 않아 GC 압력이 없고, 캐시 지역성이 좋습니다. 용량이 부족하면 두 배로 늘리므로 사실상 객체 풀 역할을 합니다.
- 위치는 Float64를 씁니다. Float32를 쓰면 메모리가 절반이 되지만, 10만 마리 × 약 20필드 × 8B ≈ 16MB 수준이라 정밀도를 우선했습니다.

### D3. 사망은 플래그 → 틱 끝에서 순서 유지 압축
틱 도중에는 `alive=0`만 기록합니다. 따라서 공간 격자의 인덱스가 틱 내내 유효하고, 죽은 개체는 그 즉시 모든 상호작용에서 빠집니다. 압축은 순서를 유지합니다(swap-remove를 쓰지 않음). 덕분에 결정론이 단순해지고 인덱스와 나이 사이에 편향이 생기지 않습니다. 신생아는 상호작용 단계가 끝난 뒤 배열 끝에 추가합니다.

### D4. 공간 해시 = 균일 격자 + 카운팅 정렬, 매 틱 재구성
셀 크기는 40단위이고, 종별로 3개 격자(피식자, 포식자, 먹이)를 둡니다. 재구성은 O(n)이며 할당이 없습니다. 증분 갱신보다 단순하고, 대부분의 개체가 매 틱 움직이므로 비용 차이도 작습니다. 질의 범위는 질의 반경에 맞춰 계산합니다(포식자 도달 거리 = 자신의 반대각선 + 피식자 최대 반대각선).

### D5. 고정 시간 간격 + 시간 예산
- dt는 1/30초로 고정합니다. 속도 배율은 "실제 1초당 시뮬레이션 몇 초"를 뜻하며 틱 크기는 바꾸지 않습니다. 따라서 속도 배율과 무관하게 결과가 같습니다.
- Worker는 실시간 × 배율만큼 틱을 쌓아 두고, 한 번에 최대 14ms까지만 계산한 뒤 양보합니다. 따라잡지 못하면 밀린 틱을 **버립니다**(죽음의 나선 방지). HUD의 '실속도'가 실제 달성 배율을 보여 주고, 목표보다 느리면 강조됩니다.

### D6. 시뮬레이션과 렌더링 분리, 역압(back-pressure)
- Worker는 최대 약 30Hz로 스냅샷을 보냅니다(개체당 float 6개, 먹이당 2개, `Transferable`이라 복사 없음).
- UI가 `ack`를 보내기 전에는 최대 2개까지만 보냅니다. UI가 느려도 메시지 큐가 쌓이지 않습니다.
- 렌더 루프(rAF)는 `client.latest`를 직접 읽습니다. **프레임 데이터는 React 상태에 넣지 않습니다.**
- 새 스냅샷, 카메라, 캔버스 크기, 설정, 선택, 표시 배율 중 **하나라도 바뀌었을 때만 다시 그립니다.** 스냅샷은 약 30Hz이고 일시정지 중에는 아무것도 변하지 않으므로, 매 rAF마다 그리면 절반 이상이 같은 화면의 반복입니다.
- **HUD의 FPS는 실제로 그린 프레임 수/초**입니다. rAF 호출 횟수가 아닙니다. 따라서 실행 중에는 스냅샷 주기(약 30)에 가깝고, 일시정지 중에는 0입니다.
- **캔버스 리사이즈는 같은 콜백 안에서 다시 그립니다.** `canvas.width/height`를 바꾸면 비트맵이 지워지고, `alpha:false` 컨텍스트에서는 불투명 검정이 됩니다. 한 프레임은 rAF → 레이아웃 → ResizeObserver → 페인트 순으로 진행되므로, 다음 rAF까지 기다리면 지워진 캔버스가 그대로 화면에 칠해집니다. 패널 전환 애니메이션(200ms) 동안에는 매 프레임 크기가 바뀌어 화면 전체가 검게 보였습니다(커밋 `4bc3ed7`까지 있던 버그로, 리사이즈 프레임의 97~100%가 검었음). 지금은 ResizeObserver 콜백에서 즉시 다시 그리며, `e2e/smoke.mjs`가 같은 프레임 안에서 픽셀을 검사해 회귀를 막습니다.
- 초기화할 때마다 `epoch`을 올려서 이전 세계에서 온 프레임을 버립니다.

### D7. 결정론
- RNG는 sfc32이고, 시드 하나를 splitmix32로 확장합니다. 엔진의 모든 무작위는 이 RNG 하나로만 얻습니다(`Math.random` 금지).
- 같은 시드, 같은 설정, 같은 틱 수면 같은 상태가 나옵니다. 몇 틱씩 나눠 실행해도 같습니다(테스트 `reproducibility`).
- 실시간으로 설정을 바꾸면 그 시점부터 궤적이 달라집니다. 재현하려면 설정을 저장하고 초기화하세요.

### D8. 진화 방향을 코드로 강제하지 않음
선택은 오직 다음에서만 생깁니다: 충돌 기하(몸 모양), 이동 거리(속도 × 활동성), 에너지 비용, 번식 조건. 돌연변이는 평균 0인 정규분포이고, 테스트로 무편향성을 확인합니다. 대조군 테스트(돌연변이 끔)에서는 형질이 절대 변하지 않습니다.

### D9. 렌더링: 배치 Path를 청크로 나누고 작은 몸은 단순화
- 종마다 512개 단위로 Path를 만들어 한 번에 `fill()`합니다. 처음에는 전 개체를 Path 하나에 넣었는데, Skia 래스터라이저가 초선형으로 느려져 2만 마리에서 프레임당 1.6초가 걸렸습니다(BENCHMARK.md 참조).
- 화면에서 3px 미만인 몸은 회전 없이 정사각형 하나로 그립니다(삼각함수 생략).
- 확대했을 때는 화면 밖 개체를 건너뜁니다.

### D10. WebGL/WASM은 아직 도입하지 않음
측정 결과 1만~2만 마리까지 Canvas 2D로 60 FPS가 나오고, 엔진은 2만 마리에서 틱당 약 3.4ms입니다. 다음 병목은 엔진 쪽 감지(시야) 질의입니다. 따라서 도입 순서는 감지 빈도 축소 → 다중 Worker → WASM 순이 합리적입니다. 자세한 내용은 BENCHMARK.md에 있습니다.

### D11. 화면 구성: 시뮬레이션 우선, 나머지는 점진적으로 공개
- **레이아웃**: 상단 바(지표를 실험·개체·성능으로 그룹화) / 중앙 캔버스 / 오른쪽 설정 패널 / 아래 통계 패널. 설정은 너비, 통계는 높이를 애니메이션해서 캔버스를 **밀어냅니다**(push). 닫으면 그 공간이 즉시 캔버스로 돌아옵니다. 1024px 미만에서는 같은 콘텐츠가 오버레이 드로어와 바텀시트로 바뀝니다.
- **실행 컨트롤은 패널에서 분리**: 시작, 정지, 1틱, 초기화, 속도는 캔버스 아래 도크에 두었습니다. 설정을 닫아도 실험을 조작할 수 있어야 하기 때문입니다. 도크의 높이를 측정해서, 자동 맞춤 시 월드가 도크 뒤에 가려지지 않도록 여백으로 넘깁니다.
- **자동 맞춤과 사용자 시점**: 카메라는 사용자가 이동·확대하기 전까지 월드 전체를 맞춰 유지합니다(캔버스가 리사이즈되면 다시 맞춤). 수동 조작 후에는 시점을 보존하고, `맞춤` 버튼이 자동 맞춤을 되살립니다. 따라서 패널 토글이 사용자의 맥락을 깨지 않습니다.
- **속도 슬라이더는 로그 스케일**(0.25×~50×)입니다. 2×는 "두 배 빠름"이므로 곱셈 척도가 자연스럽습니다. 1·2·5·10× 눈금에 스냅하되, 스냅된 값이 썸 위치를 다시 끌어당기지 않도록 원시 위치를 따로 보관합니다(그렇지 않으면 키보드로 눈금을 벗어날 수 없습니다). 매핑은 순수 함수([speed.ts](../src/ui/speed.ts))로 테스트합니다.
- **리렌더링 격리**: 라이브 수치(HUD), 선택 개체 카드, 멸종 알림은 각자 폴링하는 컴포넌트입니다. `App`과 설정 패널은 시뮬레이션이 돌아가는 동안 다시 렌더링되지 않습니다. 설정 패널은 닫혀 있어도 마운트를 유지하고(`inert`) 섹션 상태와 스크롤을 보존하며, 통계 그래프는 펼쳤을 때만 마운트합니다.
- **상태 기억**: 패널 열림 여부와 통계 높이는 `localStorage`에 저장합니다(접근이 막혀도 동작). 좁은 화면의 오버레이는 저장하지 않고 항상 닫힌 채 시작합니다.
- **접근성**: 토글은 아이콘과 함께 "설정 열기/닫기", "통계 열기/닫기" 텍스트를 가지며 `aria-expanded`/`aria-controls`를 설정합니다. 닫힌 패널은 `inert`로 포커스와 읽기 대상에서 빠집니다. 오버레이는 열릴 때 포커스를 안으로 옮기고 Esc로 닫으면 토글로 돌려줍니다. 높이 조절 손잡이는 `role="separator"`이며 방향키로 조작합니다. `prefers-reduced-motion`이면 전환을 끕니다.

### D12. 개체 표시 크기는 물리 크기와 분리
- 몸 크기는 유전 형질이며, 충돌·에너지·선택에 직접 쓰입니다. 그래서 잘 보이게 하려고 유전자 초기값이나 범위를 키우지 **않았습니다**. 바꾸면 모든 프리셋의 동역학과 기록된 실험 결과가 달라집니다.
- 대신 렌더러가 세 값을 독립적으로 다룹니다([render/sizing.ts](../src/render/sizing.ts)).
  - **물리 크기**: 유전자 값. 렌더러는 읽기만 합니다.
  - **표시 배율**: 기본 ×1.5. 사용자가 1~3배로 바꿀 수 있고, 브라우저에 저장되며 실험 설정 파일에는 들어가지 않습니다.
  - **카메라 확대율**: 위와 무관합니다.
- 최소 표시 크기(반폭 1.25px)는 축소했을 때 개체가 사라지지 않게 합니다.
- 밀도 제한: 평균 개체 간격의 55%를 넘지 않도록 표시 배율을 1 쪽으로 줄입니다(1보다 작게는 줄이지 않음). 세계 면적과 개체 수로만 계산하므로 확대·축소해도 크기가 튀지 않습니다. 기본 세계(1200×800)에서 약 3,500마리까지는 ×1.5가 그대로이고, 5,000마리면 약 ×1.27, 20,000마리면 ×1입니다.
- **오해 방지**: 배율이 1이 아니면 범례에 `표시 ×1.5`가 보입니다. 개체를 선택하면 실제 충돌 직사각형이 파란 윤곽으로 그려집니다. 클릭 판정도 그려진 크기를 기준으로 합니다.
- **형태**: 화면에서 충분히 크면 몸 앞쪽이 한 반폭만큼 뾰족해져 진행 방향이 보입니다. 이 코는 충돌 직사각형 안쪽을 깎아 만든 것이라 바깥으로 튀어나오지 않습니다. 반폭 3px 미만에서는 단순 사각형, 1.5px 미만에서는 회전 없는 정사각형으로 그려 비용을 줄입니다.

## 확장 지점

| 요구사항 | 현재 구조에서의 위치 |
|---|---|
| 새로운 종 | `Species`는 현재 0과 1입니다. 종별 설정을 `config.species[]` 배열로 바꾸고, 종마다 격자를 두며, 먹이사슬 관계를 표로 정의하면 됩니다. |
| 사용자 정의 유전자 | `GENE_KEYS`와 stride가 배열 기반입니다. 유전자 표현형 매핑만 엔진의 사용처에 연결하면 됩니다. |
| 유성생식과 재조합 | `inheritGenome`은 부모 오프셋을 받습니다. 두 번째 부모 오프셋과 교차 함수를 추가하면 됩니다. |
| 신경망 행동 | `updateCreature`의 결정, 감지, 이동 단계를 정책 함수로 교체합니다. 가중치는 유전체 뒤에 붙는 가변 길이 블록이 됩니다. |
| 장애물과 다중 구역 | 이미 `zones: ZoneConfig[]` 배열입니다. 장애물은 같은 충돌 단계에 추가합니다. |
| 계통 추적 | 이미 `parentId`와 `generation`이 있습니다. 출생·사망 이벤트 로그를 추가하면 계통수를 만들 수 있습니다. |
| 반복 실험과 비교 | `scripts/replicate.ts`가 원형입니다. Worker 여러 개로 브라우저 UI에 붙일 수 있습니다. |
| CSV 내보내기, 설정 저장 | 구현됨 |
